# quick-throttle-runner

Generates two bash scripts (`qv-throttle.apply.sh` and
`qv-throttle.clear.sh`) that consume `throttle.ini` (from
[quick-throttle-apply](../quick-throttle-apply/)) and per-axis profile
files (from [quick-throttle](../quick-throttle/)) to apply/clear VM
resource throttles via `virsh`.

## Output

```
.qv-limits/
├── qv-throttle.apply.sh    # mode=755, requires <throttle.ini> arg
└── qv-throttle.clear.sh    # mode=755, requires <throttle.ini> arg
```

Both scripts validate the mapping file's `format_version` matches the
version baked into the script at terraform-time (see `local.format_version`
in `main.tf`). Mismatch → script aborts with an error.

## Usage

```hcl
module "throttle_runner" {
  source = "git@github.com:mironx/quick-virt.git//modules/quick-throttle-runner?ref=v0.3.0"

  output_dir = path.root
}
```

After `terraform apply`:

```bash
# Apply current state of throttle.ini
bash .qv-limits/qv-throttle.apply.sh .qv-limits/throttle.ini

# Clear all throttles for VMs listed in throttle.ini
bash .qv-limits/qv-throttle.clear.sh .qv-limits/throttle.ini
```

## Semantics

### apply.sh

For each `[vm-name]` section in throttle.ini:

| Field | Value | Action |
|---|---|---|
| `cpu_profile`         | `null` or empty | `virsh schedinfo --set vcpu_quota=-1` (unlimited) |
| `cpu_profile`         | `cpu-X.ini`     | load file, parse `[cpu]`, apply via `virsh schedinfo` |
| `disk_profile.<dev>`  | `null` or empty | clear all dims via `virsh blkdeviotune` (zero) |
| `disk_profile.<dev>`  | `disk-X.ini`    | load file, parse `[io.<dev>]` + `[io.<dev>.burst]`, apply via `virsh blkdeviotune` |
| `network_profile.<i>` | `null` or empty | clear in/out via `virsh domiftune` (zero) |
| `network_profile.<i>` | `network-X.ini` | load file, parse `[net.<i>.{in,out}bound]`, apply via `virsh domiftune` |

CPU mode resolution:
- Both `period_us` AND `quota_us` set → RAW (verbatim)
- Only `percent` set → PERCENT, `quota_us = vcpu × period × percent / 100`
  (vcpu queried from `virsh dominfo` at apply time, period defaults to 100000)
- Neither set → SKIP this axis

Network interface index → `vnetN` name is resolved per VM via `virsh domiflist`
(rows starting from NR=3 = iface 0).

### clear.sh

For each `[vm-name]` section, **unconditionally** zeroes:
- CPU (`vcpu_quota=-1`)
- Every disk listed via `disk_profile.<dev>` keys (regardless of value)
- Every iface listed via `network_profile.<idx>` keys (regardless of value)

Profile files are NOT read by clear.sh — it's purely a "back to no throttle"
pass driven by the structure of throttle.ini.

## Format version coordination

Bump `local.format_version` in `main.tf` **and** the `format_version = X`
lines in:
- `quick-throttle/templates/{cpu,disk,network}.ini.tmpl`
- `quick-throttle-apply/templates/throttle.ini.tmpl`

…whenever you make a breaking change to any section/key naming. Scripts
generated by this module will refuse to read `.ini` files with a different
version (defensive check).

## Outputs

| Output | Type | Description |
|---|---|---|
| `apply_script` | `string` | Path to `qv-throttle.apply.sh` |
| `clear_script` | `string` | Path to `qv-throttle.clear.sh` |
| `format_version` | `number` | Version baked into the scripts (currently 1) |

## Persistence

Both scripts use `virsh ... --live --config`:
- `--live`: change applied immediately to the running domain (cgroup update)
- `--config`: change persisted in the libvirt XML on disk (survives VM reboot)

Clearing also uses `--config`, so XML is cleaned up cleanly on rollback.
